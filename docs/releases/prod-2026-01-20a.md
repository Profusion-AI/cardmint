## Summary

Welcome discount codes with Stripe-enforced single-use, lot+welcome discount stacking with cent drift fix, and Stripe-derived totals as source of truth in webhooks.

## Changes

### Welcome Codes (Stripe-Enforced Single-Use)

- **New service:** `welcomeCouponService.ts` - manages welcome coupon creation/validation
- **Stripe Promotion Codes:** Welcome discounts now use native Stripe Promotion Codes with `max_redemptions: 1`
- **Migration:** `20260120_welcome_coupons.sql` - adds `welcome_coupons` table to track email→code assignments
- **Klaviyo integration:** Subscribe endpoint now provisions welcome code and sends via Klaviyo event

### Lot + Welcome Stacking (Cent Drift Fix)

- **Largest-remainder allocation:** `allocateCentsProportionally()` helper guarantees `sum(unit_amounts) === lotDiscount.finalTotalCents`
- **Deterministic tie-breaker:** Lower index wins when fractional cents are equal, ensuring cross-runtime consistency
- **Invariant check:** Throws if allocated prices don't sum to target (detects bugs immediately)
- **Stacking approach:** Lot discount applied via line-item prices, welcome via `promotion_code`

### Stripe-Derived Totals (Webhook Hardening)

- **Source of truth:** Webhook now persists Stripe's `amount_subtotal - total_details.amount_discount` instead of metadata
- **Discrepancy logging:** Warns if computed total differs from Stripe (Stripe wins)
- **Tax future-proofing:** Uses `stripeTaxCents` instead of hardcoded `0`

### EverShop Extension Fix

- **PWE endpoint:** Now accepts JSON-string bodies and coerces boolean-ish values (`"true"` → `true`)
